# P3-11 — Final Regression and Evidence Gate

## Purpose

P3-11 closes the implementation regression phase before final PoE documentation
and release work. Earlier issues prove individual data structures and features;
this gate verifies that the completed application still builds, tests and runs
as one system after the Part 3 integrations.

The gate does **not** manufacture a benchmark claim. Large telemetry and mesh
results are captured separately in the JSON evidence generated by P3-11
Commits 1 and 2. The final runner validates those artifacts and records the
actual exit status of the standard project quality gates.

## Required evidence before the final gate

The following files must already exist:

- `docs/evidence/part3/telemetry-10k.json`
- `docs/evidence/part3/telemetry-50k.json`
- `docs/evidence/part3/mesh-256.json`
- `docs/evidence/part3/mesh-1000.json`

The two telemetry artifacts were produced by the earlier Commit 1 harness and
use its own evidence schema. The final gate therefore validates their requested
10,000/50,000 reading scale, measured/count data, and any explicit pass/failure
indicator without rewriting that committed evidence into the later mesh JSON
schema. A recognised explicit failure still fails the gate. Each artifact is
also recorded by SHA-256 in the final report, with its original run ID when one
was emitted by the producing harness.

The mesh artifacts use the later explicit `"result": "PASS"` convention and
receive additional invariant checks: the expected fixture
size, complete reachability after the island bridge, complete disconnection
when all gateway links are removed, successful route restoration, and proof
that rejected requests did not mutate graph version or link count.

## Final automated runner

From the repository root, first verify the runner itself:

```bash
python3 scripts/tests/test_verify_part3_final_regression.py
python3 -m py_compile \
  scripts/verify_part3_final_regression.py \
  scripts/tests/test_verify_part3_final_regression.py
```

Then run the complete local release gate, including Docker:

```bash
python3 scripts/verify_part3_final_regression.py --with-docker
```

The runner executes, in order:

1. the audited `.NET` restore;
2. `dotnet format --verify-no-changes`;
3. Release build;
4. the complete backend regression;
5. clean frontend dependency installation and high-severity audit;
6. ESLint and Prettier verification;
7. the production Vite build;
8. the focused P3-11 integrated browser regression;
9. the complete Playwright regression;
10. Docker Compose configuration, image build and healthy startup;
11. Nginx-proxied `/ingestion`, `/realtime`, `/topology`, API topology reads,
    health endpoints and `/hubs/realtime` negotiation;
12. normal `docker compose down` **without deleting named volumes**.

A successful run writes:

`docs/evidence/part3/p3-11-final-regression.json`

The report contains command exit codes, elapsed observations and bounded output
tails. It intentionally does not scrape or invent a future test count. The
terminal remains the authoritative place to read the exact backend and browser
counts produced by that run.

## Security and deployment boundaries

The Docker smoke test uses the existing Nginx boundary. Only the frontend port
is expected to be host-published; API and SignalR requests flow through the
proxy. The script never enables physical devices, never inserts secrets into
tracked files, and never executes `docker compose down --volumes`.

The root `.env` / environment must already provide the attachment encryption
key required by the existing Compose deployment. That secret is not copied
into the evidence JSON.

## P3-11 completion condition

P3-11 is ready for its pull request when:

- telemetry 10k and 50k evidence passes;
- mesh 256 and 1000 evidence passes;
- the integrated three-pillar browser regression passes;
- the existing full backend and Playwright suites pass;
- the Docker proxy smoke passes; and
- `git diff --check` is clean with only intended P3-11 evidence and test files
  staged for the final commit.
