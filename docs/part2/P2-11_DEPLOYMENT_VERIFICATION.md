# P2-11 — Production Routing, SignalR and Container Boundary Verification

## Purpose and scope

Commit 2 extends the **existing four-job GitHub Actions workflow**, rather than
creating another deployment or changing application behaviour. The production
smoke test exercises the same public origin used by the browser:

```text
Browser / CI host
    |
    | http://127.0.0.1:18080 (CI) or http://localhost:8080 (local)
    v
React / Nginx container (published port)
    |                       |
    | /api/*                | /hubs/* (WebSocket Upgrade)
    v                       v
ASP.NET Core API container (private Docker network, internal port 8080)
    |
    +-- Background telemetry processing worker
```

No sensor registrations, telemetry, commands, undo operations or operator
interactions are generated by the smoke test. The tests do **not** require a
pre-seeded recommendation or durable process-local state.

## New verification in Commit 2

| Layer | Actual contract checked | Where |
|---|---|---|
| React / Nginx | Direct `GET /realtime` returns the built Smart-X HTML shell | `scripts/verify_part2_docker_boundaries.py` |
| Snapshot API | `GET /api/realtime/snapshot` returns a consistent device count, rows and worker snapshot | Same script |
| Conditions | `GET /api/realtime/snapshot/active-conditions` returns an internally consistent HashSet-backed active-condition snapshot | Same script |
| Recommendations | `GET /api/realtime/recommendations` exposes a typed, read-only prediction response, even when there is insufficient evidence | Same script |
| Queue worker | `GET /api/realtime/processing` reaches `Waiting` or `Processing` and has no reported failure | Same script |
| Dashboard SignalR | POST negotiation offers WebSockets; the same Nginx path supports a valid HTTP 101 WebSocket upgrade | Same script; original dashboard negotiation step retained |
| Part 2 SignalR | POST negotiation offers WebSockets; the same Nginx path supports a valid HTTP 101 WebSocket upgrade | Same script |
| Runtime privileges | Both **running containers** report nonzero numerical UIDs | New step in `Docker Deployment` |

The WebSocket check validates the `Sec-WebSocket-Accept` signature and then closes
the connection. It is **not** a full SignalR message-exchange test. The existing
Playwright tests remain responsible for proving real browser refresh, reconnect
behaviour, telemetry processing and command-state updates.

## Existing guards retained, not weakened

The original `.github/workflows/ci.yml` still requires all four jobs:

1. **Backend:** NuGet audit, formatting, Release build and complete .NET tests.
2. **Frontend:** `npm ci`, high-severity npm audit, ESLint, Prettier and build.
3. **Playwright E2E:** actual ASP.NET Core + Vite browsers; includes live
   invalidation/reconnect, Suggested Actions, execution and Undo regression.
4. **Docker Deployment:** Compose validation, image build, image-level non-root
   users, health-gated startup, live container health, root React endpoint,
   API proxy, dashboard negotiation, private API port verification, failure logs
   and guaranteed cleanup.

No `continue-on-error`, `|| true`, weakened audit levels, disabled tests or
additional public API port mappings are introduced.

Existing `compose.yaml`, both Dockerfiles and `nginx.conf` require **no changes**:
the configured `/api/` and `/hubs/` proxy locations already cover Part 2.

## Local verification from a clean working tree

The API requires a real, locally configured AES key. Do not commit or print it.
If the project's ignored `.env` already contains
`SMARTX_ATTACHMENT_ENCRYPTION_KEY_BASE64`, reuse that local configuration.

```bash
# Run from repository root. Do not display resolved Compose secrets.
docker compose config --quiet
docker compose up -d --build

docker compose ps
curl --fail --silent --show-error http://127.0.0.1:8080/healthz
curl --fail --silent --show-error http://127.0.0.1:8080/api/health

python3 scripts/verify_part2_docker_boundaries.py \
  --base-url http://127.0.0.1:8080
```

If the project uses a nondefault `SMARTX_HTTP_PORT`, replace `8080` in the
commands with that public **Nginx** port. Do not address the API container
from the host; that would bypass the reverse proxy being tested.

**Required result:** every check prints `PASS`, followed by
`All Part 2 production routing and SignalR checks passed`. Any failed request,
invalid JSON contract, stopped worker, negotiation failure or missing WebSocket
upgrade exits nonzero.

Check actual container user IDs:

```bash
# Output must be numeric and greater than zero for each service.
docker compose exec -T api id -u
docker compose exec -T client id -u
```

The CI job separately checks the API container's `HostConfig.PortBindings` to
prove its internal port 8080 is **not** published to the host. Do not interpret
Compose `expose:` as host publication.

After testing:

```bash
# Preserves the encrypted attachment volume in normal local development.
docker compose down
```

Only the **CI job** uses `docker compose down --volumes --remove-orphans`
because its encryption key and attachment volume are disposable per run.

## Troubleshooting

- **`/realtime` returns JSON or 404:** inspect Nginx SPA fallback and frontend
  image contents. Do not add separate app routes to the API.
- **`/api/realtime/*` returns HTML:** the `/api/` proxy may not be active;
  inspect the current Nginx configuration and API health.
- **Worker remains `Starting` / reports `Faulted`:** inspect `docker compose
  logs api`. An HTTP 200 health check alone is insufficient.
- **Negotiation passes but WebSocket upgrade fails:** verify Nginx forwarding
  of `Upgrade` and `Connection` headers; confirm the API `/hubs/*` mapping.
- **Runtime UID is zero:** check the effective user in Dockerfiles and Compose;
  do not make the assertion optional.
- **API port unexpectedly published:** remove the host `ports:` mapping from
  the `api` service. Keep the `client` service as the only public ingress.

After any correction, rerun the normal .NET, frontend, Playwright and Docker
checks; do not bypass a failing CI job to merge the P2-11 PR.
